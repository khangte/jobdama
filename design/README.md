# Notion 연결 UI 시안

`notion-connection.html`은 API를 호출하지 않는 독립적인 디자인 검토용 시안이다. 앱 코드는 변경하지 않는다.

브라우저에서 파일을 열고 하단 상태 전환 버튼으로 미연결, 연결 입력, 연결 정보, 해제 확인, 연결 오류를 확인한다. 입력 폼에 공백 없는 임의의 값을 넣으면 연결된 화면을 체험할 수 있다. 실제 토큰을 입력할 필요는 없다.

## 설계 의도

- 미연결은 오류가 아닌 준비 단계로 표현한다. 작은 파란 안내와 연결 버튼만 본문에 배치한다.
- 토큰과 DB 입력은 모달로 모아 공고 목록과 분리한다. 환경변수 이름은 접을 수 있는 도움말로 제공한다.
- 연결 후 상단 상태 버튼에서 채용 지원 관리 DB와 연결 해제를 확인한다.
- 해제 확인에서 새 공고 저장 중단과 기존 Notion 데이터 유지, 재시작 시 환경변수 재적용을 안내한다.
- 토큰 마스킹, 보기 전환, 요청 중 상태, 입력 오류, 연결 오류, 성공 안내를 포함한다.

## 로컬 검증

- Chromium에서 연결 입력 → 연결 정보 → 해제 취소 → 해제 완료 흐름을 검증했다.
- 토큰 표시 전환, 연결 후 입력값 초기화, 연결 오류 표시를 확인했다.
- 1440px 데스크톱과 390px·320px 모바일에서 가로 넘침이 없음을 확인했다.
- `notion-*.png`는 해당 브라우저에서 캡처한 시안 이미지다.

## Penpot 반영 상태

- 사용자 요청에 따라 연결된 `jobdama` 파일의 `Page 1`에 편집 가능한 보드 9개를 추가했다.
- `05`~`09`: 데스크톱 미연결, 연결 입력, 연결 정보, 해제 확인, 연결 오류.
- `10`~`13`: 모바일 연결 입력, 연결 정보, 해제 확인, 미연결.
- 원본 화면 옆에 배치했으며, 새 보드는 텍스트와 도형으로 구성했다. UI를 캡처한 이미지는 넣지 않았다.
- 연결·취소·닫기·해제·연결 유지의 주요 화면 이동 19개를 연결했다. 실제 API 호출은 하지 않는 디자인 프로토타입이다.
- Penpot 렌더링을 확인했고 입력·해제 모달의 텍스트가 컨테이너 안에 있는지 검증했다.
- 최초 이관 당시 식별자는 `penpot-handoff.json`에 기록했다. 현재 페이지 구성과 식별자는 `penpot-organization.json`을 사용한다.

### 현재 페이지 구성

- `01 · 데스크톱`: 화면 보드 18개. 공고 담기·Notion 연결·자동 수집·수집 조건을 영역 제목과 배치로 구분한다.
- `02 · 모바일`: 화면 보드 12개. 데스크톱과 같은 기능·상태 번호 규칙을 사용한다.
- `03 · 컴포넌트`: 부품 보드 11개와 재사용 원본 32개. 일반 컴포넌트 4개, 결과 카드 Variant 14개, 사이트 집계·필터 Variant 4개, 수집 조건 Variant 10개를 관리한다.
- `90 · 보관함`: 교체된 화면을 보관할 빈 페이지. 원본이 없는 이전 컴포넌트 메타데이터 10개는 별도로 라이브러리의 `보관/원본 없는 이전 Variant` 경로로 분류했다.
- 화면과 부품 보드는 각 페이지의 최상위에 두어 캔버스에 보드 제목이 표시되도록 한다. 화면 내부 레이어는 기존 계층을 유지한다.
- 페이지를 옮긴 모바일·부품 보드의 크기와 텍스트를 대조했고, 모바일 화면 이동 연결 13개를 새 보드로 맞췄다. 데스크톱 16개·모바일 3개 컴포넌트 참조를 새 원본으로 교체한 뒤 내용 보존 검사를 통과했다.
- Variant 원본을 일반 컴포넌트처럼 분리하면 `variant-not-main` 등의 무결성 오류가 생긴다. 결과 카드는 인스턴스에서 복사한 뒤 상태 속성을 유지하는 새 Variant 세트로 구성했다.
- 최종 파일 무결성 오류는 0개이며, 데스크톱 16개·모바일 13개 화면 이동의 대상과 컴포넌트 참조가 유효함을 확인했다. 페이지별 변경은 저장 체크포인트를 생성한 뒤 다음 페이지로 이동했다.
- 로컬 MCP의 npm 배포본은 2.15.4이며 Penpot은 2.19.0이라 버전 경고가 남는다. 데스크톱 렌더링과 모바일 경고 화면 렌더링을 확인했다. 모바일 이미지는 비동기로 내보내기를 시작하고 완료 후 파일을 받아 서버의 30초 작업 제한 안에서 검증했다.

## 연결 설정 변경

- 관심 기업 리스트 DB 입력란, 연결 정보 행, `COMPANY_DATA_SOURCE_ID` 도움말을 로컬 시안과 Penpot에서 제거했다.
- 앱의 연결 API와 설정에는 별도 기업 DB 입력이 이미 제거되어 있어 중복 수정하지 않았다. 기업 DB는 채용 DB의 기업명 relation에서 자동으로 찾는다.
- 변경 후 Chromium 시안 검증과 연결 API·Notion 저장소 테스트 36개가 통과했다. Penpot 입력 모달·연결 정보 렌더링과 텍스트 넘침도 확인했다.

## 자동 수집 화면

`collect-screen.html`은 `/collect` 구현 전에 화면 상태를 확인하는 로컬 시안이다. 주소 뒤에 `?state=empty|running|done|disconnected`를 붙여 상태를 바꿀 수 있다. 실행 버튼은 실행 중·Notion 미연결 상태에서 비활성으로 표시한다. 수집 API는 호출하지 않는다.

다음 7개 보드를 Penpot `jobdama` 파일에 편집 가능한 도형·텍스트 레이어로 반영했다. 보드와 컴포넌트 식별자는 [Penpot 구성 기록](penpot-organization.json)에, 구현 세부 사항은 [로컬 핸드오프](collect-handoff.md)에 있다.

완료 상태 캡처: [데스크톱](collect-desktop.png) · [모바일](collect-mobile.png)

| 보드 | 상태 | 구현 대응 |
| --- | --- | --- |
| D03-01 · 수집 / 기록 없음 | 첫 방문, 실행 기록 없음 | `GET /collect`에서 `run == null` |
| D03-02 · 수집 / 실행 중 | 실행 중, 버튼 비활성, 처리 중 카드 | `running == true` |
| D03-03 · 수집 / 완료 | 사이트 오류, 제외 사유, 전체 필터 | 완료된 `run` |
| D03-04 · 수집 / Notion 미연결 | 버튼 비활성, 메인 연결 링크 | `notion_ready == false` |
| M03-01 · 수집 / 기록 없음 | 390px 기록 없음 | 모바일 `run == null` |
| M03-02 · 수집 / 실행 중 | 390px 실행 중 | 모바일 `running == true` |
| M03-03 · 수집 / 완료 | 390px 완료, 사이트별 카드 집계 | 모바일 완료된 `run` |

- 구성 순서는 상태 → 실행 → 사이트별 집계 → 공고별 결과 → 선별 조건이다. 기록이 없을 때는 집계 대신 기록 없음 카드를 보여준다.
- 데스크톱 집계는 표, 모바일 집계는 사이트별 카드 목록이다. 결과 카드 상태 `저장 안 함`은 기존 `--info`·`--info-bg`, `저장 대상`은 기존 `--blue`·`--run-bg`를 사용한다.
- `03 · 컴포넌트`의 기존 결과 카드 `Status`·`Viewport` Variant 세트에 두 상태를 각각 데스크톱·모바일로 추가했다. `사이트 집계 표 행`은 오류 줄 유무, `상태 필터 탭`은 선택 여부로 각각 2개 Variant를 만들었다.
- 로컬 시안은 Chromium에서 1440px·390px·320px로 상태별 렌더링을 확인했다. 가로 넘침이 없었고, 실행 중·미연결 상태의 버튼 비활성과 모바일 메뉴·Notion 상태 표시를 확인했다.
- Penpot에서 새 보드 7개의 도형·텍스트 경계, Variant 오류, 화면 이동 대상의 유효성을 검사해 모두 오류 0개를 확인했다. 데스크톱·모바일 보드와 신규 부품의 PNG 내보내기를 눈으로 확인했다. 전체 Penpot 파일 내보내기 검사는 MCP의 `No matching clause` 오류로 수행되지 않았다.
- 마지막 화면 이동·크기 수정까지 포함한 저장 체크포인트는 `task9/collect-screen-final`이다.

## 수집 조건 화면

`collect-settings.html`은 `/collect/settings` 구현 전에 상태와 입력 구성을 확인하는 로컬 시안이다. `?state=default|error|saved|broken`으로 기본, 입력 오류, 저장 완료, 설정 파일 오류를 전환한다. 실제 API는 호출하지 않는다. 구현 세부 사항은 [핸드오프](collect-settings-handoff.md)를 따른다.

기본 상태 캡처: [1440px 데스크톱](collect-settings-desktop.png) · [390px 모바일](collect-settings-mobile.png). Penpot 보드·컴포넌트 식별자는 [구성 기록](penpot-organization.json)에 있다.

| Penpot 보드 | 상태 | 구현 대응 |
| --- | --- | --- |
| D04-01 · 수집 조건 / 기본 | 저장된 기본값 | `/collect/settings`, 오류·배너 없음 |
| D04-02 · 수집 조건 / 입력 오류 | 사이트 0개, 검색어 31자 | 422 필드 오류·폼 위 요약 |
| D04-03 · 수집 조건 / 저장 완료 | 실행 중 저장 | 실행 중 안내·저장 성공 문구 |
| D04-04 · 수집 조건 / 설정 파일 오류 | 설정 파일 읽기 실패 | 기본값·경고 배너 |
| M04-01 · 수집 조건 / 기본 | 390px 기본값 | 검색 조건 1열, 버튼 전체 폭 |
| M04-02 · 수집 조건 / 입력 오류 | 390px 두 필드 오류 | 요약·필드 오류, 버튼 전체 폭 |

- `D03-03 · 수집 / 완료`의 선별 조건을 검색어부터 본문 필수 신호까지 12개 항목으로 고치고 `조건 바꾸기`를 `D04-01`에 연결했다. 모바일 `M03-03`도 같은 정보를 1열로 표시하고 `M04-01`에 연결했다. `D04-*`·`M04-*`의 `← 자동 수집`은 각각 완료 화면으로 돌아간다.
- `03 · 컴포넌트`에 `선택 상자 필드`(기본·포커스·오류), `여러 줄 입력 필드`(기본·오류), `안내 배너`(경고·정보), `체크 칩`(선택·비선택·포커스) Variant를 추가했다. 기존 URL 입력 부품과 용도가 달라 별도 세트로 두었다.
- 로컬 시안을 Chromium에서 1440px의 네 상태와 390px·320px의 기본·오류 상태로 렌더링했다. 가로 넘침과 필드의 화면 밖 배치가 없고, 모바일 입력은 1열, 버튼은 전체 폭으로 쌓인다. 기본값 불러오기·오류 표시도 브라우저에서 확인했다.
- Penpot의 새 보드 6개와 변경한 완료 보드에서 도형·텍스트 경계 오류 0개, 신규 Variant 오류 0개, 화면 이동 대상 오류 0개를 확인했다. 데스크톱·모바일 보드를 PNG로 내보내 눈으로 확인했다. 마지막 저장 체크포인트는 `task6/collect-settings`다.
