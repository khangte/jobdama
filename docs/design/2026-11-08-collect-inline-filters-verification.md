# 자동 수집 인라인 조건 폼 검증

- 기준 계획: `docs/superpowers/plans/2026-11-08-collect-inline-filters.md`, Task 2.
- 작업 브랜치: `feat/daily-collector-routine-web`.
- 사용자 지시에 따라 기존 미커밋 구현 위에서 프론트엔드만 수정했다. Penpot 작업과 커밋은 하지 않았다.
- 이번 재시도의 수정 파일: `app/static/app.js`, `app/static/style.css`, 이 검증 문서. 시작 시 존재한 서버·템플릿·테스트 변경은 유지했다.

## 수정한 문제

1. 모바일에서 저장 동작 줄의 그리드 열이 내용 너비로 줄어 버튼이 150px에 머물렀다. 한 열이 패널 너비를 채우도록 수정했다.
2. 일반 필드 라벨 규칙이 사이트 칩의 flex 배치를 덮었다. 칩 전용 라벨 규칙을 추가해 체크 표시 간격과 선택 상태 스타일을 유지했다.
3. 저장 응답 대기 중 추가 입력이 응답 값으로 덮이는 문제를 Chromium에서 재현했다. 저장 중 입력·기본값·저장 버튼을 잠그고 `aria-busy`를 표시한다. 실패 시 입력을 복구한 뒤 오류 필드에 포커스를 준다.
4. 저장과 실행의 중복 제출을 막는다. 진행 중 저장은 같은 Promise를 기다리고, 실행 요청 대기 중 추가 제출은 무시한다.
5. 상단 바의 좁은 화면 배치를 600px 이하로 통합했다.

## 검증 환경과 범위

실제 앱의 라우터·템플릿·정적 파일·설정 API·`CollectRunner`를 격리 서버에서 사용했다. 노션은 테스트 저장소, 채용 사이트의 응답은 저장된 픽스처로 대체했다. 외부 서비스에 실제 수집·저장은 하지 않았다. 설정·실행 결과는 `/tmp/jobdama-collect-qa/`에만 저장했으며 `.env`는 읽지 않았다.

Chromium을 Playwright로 구동하고 1440·390·320px 화면을 직접 캡처해 확인했다. 레이아웃 경계 확인은 800·601·600px에서도 수행했다.

## 확인 근거

브라우저 재현·검증 스크립트와 캡처는 `/tmp/jobdama-collect-qa/`에 있다.

- `verify_browser.py`: 필수 세 폭의 저장·실행·오류·폴링·키보드 검증.
- `browser_check.py`: 여섯 폭의 그리드·넘침·버튼 너비 확인.
- `disconnected_check.py`: 노션 미연결 저장 및 사이트 칩 키보드 조작.
- `duplicate_run_check.py`: 중복 실행 제출 및 실행 오류 후 복구.
- `final-1440.png`, `final-390.png`, `final-320.png`: 최종 화면.
- `error-1440.png`, `error-390.png`, `error-320.png`: 검증 오류 화면.
- `fetches.jsonl`: 실제 실행기가 만든 부산 검색 URL.

서버 측 추가 결함은 발견하지 않았다. 계획서의 커밋 완료조건은 이번 사용자 지시인 커밋 금지에 따라 수행하지 않았다. 최종 판정은 architect에게 요청한다.

## 리뷰 후 수정: 요청 대기 중 결과 필터 전환

리뷰에서 지적한 경합을 실제 Chromium에서 재현했다. 조건 저장을 지연한 뒤 결과 필터로 `#collect`를 실행 중 조각으로 교체하고 422를 반환하면, 수정 전에는 현재 오류가 보이지 않고 새 실행 버튼까지 활성화됐다.

`app/static/app.js`의 수집 요청 처리만 수정했다. 실패 문구를 문자열로 보관하고 요청 종료 후 현재 `collect-error`를 다시 찾아 표시한다. 버튼은 요청 시작 때 직접 비활성화한 요소와 현재 요소가 같은 경우에만 복구한다. 필터로 교체된 조각의 실행 중·미연결 비활성 상태는 그대로 둔다. 필터 이동이나 폴링을 막지 않으며 템플릿·서버 코드는 바꾸지 않았다.

1440·390px Chromium에서 다음 다섯 조합을 각각 확인했다. 모두 실제 htmx 필터 전환으로 요소 교체를 확인한 뒤 실패 응답을 전달했다.

| 대기 요청·실패 | 교체 조각 | 수정 후 결과 |
| --- | --- | --- |
| 설정 PUT 422 | 실행 중 | 현재 실행 오류 표시, 버튼 비활성 유지 |
| 설정 PUT 500 | 노션 미연결 | 현재 실행 오류 표시, 버튼 비활성 유지 |
| 수집 POST 409 | 실행 중 | 현재 실행 오류 표시, 버튼 비활성 유지 |
| 수집 POST 503 | 노션 미연결 | 현재 실행 오류 표시, 버튼 비활성 유지 |
| 수집 POST 네트워크 실패 | 실행 가능 | 현재 연결 오류 표시, 새 버튼의 활성 상태 유지 |

설정 실패는 검증용 응답, 수집 실행 중 조각은 실제 격리 실행기, 미연결 조각은 노션 미연결 격리 서버의 실제 응답을 사용했다. 두 화면 폭 모두 가로 넘침·브라우저 예외가 없고 캡처에서 오류 표시와 버튼 상태를 확인했다. 기존 중복 실행 방지·409·503·500 후 원래 버튼 복구 검사도 통과했다.
