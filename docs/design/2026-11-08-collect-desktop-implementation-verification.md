- 결과: 통과. 사용자 승인 후 `feat/daily-collector-routine-web`에서 구현했다. 커밋하지 않았다.

## 구현

- 수집 범위 패널에서 대상 사이트와 사이트별 최대 후보를 한 행에 배치했다. 검색 조건은 4열, 단어 필터는 2열로 줄였다.
- 데스크톱 제목은 `수집 범위`, `단어 필터`다. 단어 필터의 기존 네이티브 펼침 토글을 유지하고, 토글을 포함한 시작점을 검색 조건 패널과 맞췄다.
- 공고별 결과는 페이지당 10개다. 현재 번호를 9칸 중 가운데에 놓고 양옆 최대 4개를 표시한다. 경계의 없는 번호는 빈칸으로 남기며 반대편 번호로 채우지 않는다.
- 12페이지 기준 1페이지는 1~5, 2페이지는 1~6, 6페이지는 2~10, 12페이지는 8~12를 표시한다. 첫·마지막 페이지의 이전·다음 버튼은 비활성화한다.
- 페이지 상태를 교체되는 `#collect` 바깥에 보관하고, htmx 교체 후 목록과 키보드 포커스에 재적용한다. 필터 또는 수집 실행이 바뀌면 첫 페이지로 이동하며, 목록이 줄면 유효한 마지막 페이지로 보정한다.
- 필드·API·저장 및 실행 순서는 유지했다. 전체 결과 응답을 프론트엔드에서 나누므로 서버 전송량을 줄이는 변경은 아니다. 요약 막대와 사이드 패널은 추가하지 않았다.

## 실제 브라우저 검증

Playwright의 실제 Chromium에서 앱을 렌더링했다. 외부 사이트와 Notion은 로컬 검증 대역을 사용했고, 앱의 라우트·설정 저장·수집 실행 코드는 실제 코드를 사용했다.

- 데스크톱 1100·1280·1440px: 가로 넘침 없음, 검색 4열, 사이트와 후보 수의 같은 행 배치, 토글 정렬, 단어 필터 열림·닫힘, 페이지 1·2·6·12 확인.
- 승인된 서버 내보내기와 같은 배율로 비교했다. 수집 범위 높이 188px, 검색 조건 365px(시안 366px), 열린 단어 필터 208px. 단어 입력의 실제 데이터·개수 표시·네이티브 스크롤은 기존 동작을 유지한다.
- 120개 결과에서 6페이지를 선택하고 실제 2초 폴링을 5.2초 이상 기다렸다. DOM 교체를 확인했으며 6페이지와 번호 버튼 포커스가 유지됐다. 폼 편집 중 입력값과 포커스도 유지됐다.
- 결과 증가 시 페이지 유지, 감소 시 마지막 유효 페이지 보정, 새 실행·상태 필터 변경 시 초기화, 필터 후 폴링, 좁은 폭 전환 후 복귀를 확인했다.
- 실제 설정 PUT 200 → 수집 POST 202 순서, 새 근무지 설정 적용, 실행 중 편집·저장, 재접속 후 설정 유지, 422 유효성 오류, 숨겨진 단어 필터 오류의 자동 펼침과 포커스, 저장 실패 시 실행 차단, 중복 제출 방지를 확인했다.
- 1440·1280px에서 저장·실행 요청 중 결과 필터를 바꾸는 10개 오류 사례도 통과했다. 교체된 화면에 오류가 표시되며 실행 중 또는 Notion 연결 해제 상태의 비활성 버튼을 유지했다. 기록은 `pending-filter-result.txt`다.
